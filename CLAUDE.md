## 1. Что мы строим

**Slipstream** — короткий скоростной спуск в Decentraland World, оптимизированный под
мобильное приложение Decentraland.

Заезд длится 50–70 секунд. Пока игрок едет, рядом с ним едут шесть призраков — записанные
заезды реальных людей, с их именами. Когда игрок финиширует, его собственный заезд тоже
становится призраком для следующих. Если он вытеснил кого-то из таблицы, вытесненный
узнает об этом при следующем входе.

Одна фраза, которую мы повторяем в README, на BUIDL-странице и в видео:

> **Здесь никто никогда не ехал один.**

Вторая фраза, которая объясняет ретеншн:

> **Ты возвращаешься не потому, что тебя ждут. Ты возвращаешься, потому что тебя обогнали.**

Дедлайн подачи — **4 сентября 2026**, судейство **5–11 сентября**, результаты 13-го.

Судят по семи критериям: Mobile-First Experience, Social Value, Mobile UX, Performance,
Creativity, Retention, Overall Execution.

**Условия судейства определяют всю архитектуру.** Организаторы прямо потребовали, чтобы
проект работал как самостоятельный опыт без ведущего и без запланированного события в
течение всего периода судейства. Это значит:

- Судья зайдёт **один**, **с телефона**, в **случайный момент** между 5 и 11 сентября.
- Второго игрока не будет. Нас рядом не будет.
- Сервер к этому моменту будет **выключен** и начнёт холодный старт.

Отсюда единственный проектный принцип, из которого выводится всё остальное:

> **Одиночный цикл обязан быть полностью играбельным и полностью социальным
> без единого живого игрока и без работающего сервера.**

Социальность у нас асинхронная. Другие люди присутствуют как записи, а не как соединения.
Это не компромисс, это жанр: призраки в Trackmania, сообщения в Dark Souls, Streetpass.

## 3. Механика

### Трасса

Один жёлоб под уклон. Ночь, тёмный фон, эмиссивная геометрия. Не солнечно, не пастельно.
Заблудиться негде: стены жёлоба удерживают игрока, ответвлений нет.

Внутри жёлоба две траектории:

- **Дно** — безопасно и медленно.
- **Стенка** — на ней стоят кольца буста, но с неё легко соскользнуть и потерять секунду.

Вся глубина игры — сколько колец подряд игрок решится взять. Это единственная механика.
Не добавляй вторую.

### Управление

Одна кнопка. Джойстик рулит вбок, движение вперёд — под гору.

- Прыжок **отключён** через Input Modifier: кнопка не должна занимать зону большого пальца.
- Главная кнопка действия переназначена на **буст**.
- Тап внутри кольца — ускорение. Тап мимо — короткий откат скорости.
- Прицел скрыт. Целиться ни во что не надо.

### Призраки

Шесть одновременно. Подбор делает сервер:

- Если у игрока есть личный рекорд — три чуть быстрее и три чуть медленнее. Всегда есть
  догоняемая цель впереди и угроза сзади.
- Если рекорда нет — топ-3 плюс двое из середины, чтобы трасса выглядела обжитой.

**Рендер призраков — критично для производительности:**

- Пять призраков — **силуэты**: один общий низкополигональный меш, эмиссивный материал,
  цвет по месту в таблице, имя билбордом.
- Действующий рекордсмен — **единственный настоящий `AvatarShape`** в его настоящих
  wearables. Одна загрузка аватара на всю сцену, максимальный нарративный эффект.
- Если аватар рекордсмена не подгрузился за 3 секунды — фолбэк на силуэт.

**Не грузи шесть AvatarShape.** Телефон делит память между CPU и GPU, это гарантированный
провал по критерию Performance.

### Доска

Аватар едет на светящейся доске. Технически это `AvatarAttach` с якорем позиции и один
плоский меш под ногами. Доска — **чистая косметика**. Если она выглядит криво или ломает
анимацию, мы её снимаем одной строкой и остаёмся с забегом под гору, который работал с
первого дня.

### Соперничество

При финише сервер сравнивает время с таблицей. Если игрок кого-то вытеснил, вытесненному
кладётся запись в персональный inbox. При следующем входе этот человек видит одну строку:
кто и на сколько его подвинул. Больше ничего. Никаких лент, никаких уведомлений.

## 4. Технические решения — приняты, не пересматриваем без обсуждения

### Стек

- Decentraland SDK7, TypeScript.
- **Multiplayer Server**: `npm install @dcl/sdk@auth-server` и
  `npm install @dcl/js-runtime@auth-server`. Флаг `"authoritativeMultiplayer": true` в
  `scene.json` (добавляется автоматически при первой сборке на этой ветке — не удаляй).
- Хостинг сервера — Decentraland, бесплатно, деплоится вместе со сценой.
- **Никакого внешнего бэкенда.** Ни Supabase, ни Cloudflare, ни Vercel. Всё внутри.
- Персистентность — `Storage` из `@dcl/sdk/server`, только на сервере, всегда под
  `isServer()`.

### Разделение кода

```
src/
  index.ts            вход, ветвление isServer()
  client/
    setup.ts          ввод, отправка сообщений
    ui.tsx            React ECS UI
    ghosts.ts         воспроизведение призраков
    recorder.ts       запись собственного заезда
  server/
    server.ts         игровой цикл, обработчики сообщений
    timing.ts         хронометраж по чекпойнтам
    leaderboard.ts    таблица и вытеснение
  shared/
    codec.ts          кодек блоба призрака
    messages.ts       registerMessages() — импортируют обе стороны
    schemas.ts        кастомные компоненты + validateBeforeChange
static/
  ghosts.json         запечённые призраки для работы без сервера
```

`registerMessages()` вызывается один раз на верхнем уровне `shared/messages.ts`, никогда
условно и никогда внутри функции.

### Хронометраж — на сервере, не на клиенте

Сервер читает верифицированные позиции игроков через `PlayerIdentityData` + `Transform`,
опрашивает их на 10 Гц и сам засекает пересечение плоскостей чекпойнтов. Клиент **не
сообщает своё время** — он присылает только блоб призрака для воспроизведения.

Античит получается бесплатно, и это отдельная строчка в README. Ни у кого в поле такого нет.

### Кодек призрака

Сэмплирование **8 Гц**. Один сэмпл — 7 байт:

| поле | тип | единица |
|---|---|---|
| x | int16 | см, относительно начала трассы |
| y | int16 | см |
| z | int16 | см |
| yaw | uint8 | 1/256 оборота |

75 секунд × 8 Гц = 600 сэмплов = 4200 байт → base64 ≈ 5600 байт.

Лимит сообщения — около 13 КБ на практике, всё, что больше, **дропается молча, без
ошибки**. Мы влезаем, но с запасом не гигантским, поэтому:

- Размер полного 75-секундного блоба **измеряется в первый же день**, до всей остальной
  работы.
- В `shared/codec.ts` сразу закладывается разбиение на чанки (`seq`, `total`), даже если
  на старте всегда один чанк.

### Схема Storage

Storage принимает **только строки**. Объекты — через `JSON.stringify` / `JSON.parse`.

Scene-уровень:

- `lb:v1` → JSON, топ-20: `[{ addr, name, ms, ts }]`
- `ghost:v1:<addr>` → base64-блоб. **Только для тех, кто в топ-20.** Остальные удаляются
  при вытеснении, иначе хранилище растёт бесконечно.

Player-уровень (`Storage.player`):

- `pb:v1` → `{ ms, ts }` — личный рекорд
- `inbox:v1` → `[{ by, ms, ts }]` — кто подвинул, максимум 5 записей

**Правила работы со Storage, нарушение которых стоит нам данных:**

- `Storage.set()` возвращает булево и **никогда не бросает исключение**. Отброшенный
  `false` — это молча потерянный рекорд. Проверяй результат каждой записи.
- Пиши только на чекпойнтах: финиш заезда, уход игрока, дебаунс раз в 30 секунд.
  Никогда не на кадре.
- Лимит **40 одновременных host-вызовов** на весь изолят, и в него входят и Storage, и
  `signedFetch`. Лишние отклоняются сразу, не встают в очередь.
- Парси всё из Storage защитно, через try/catch и с дефолтами. Поле `version` — с первого
  дня. Схему только дополняем, не переименовываем.

### Холодный старт — вторая по важности вещь в проекте

Сервер работает только пока в сцене есть хоть один игрок. После ухода последнего он гаснет
примерно через две минуты, холодный старт в проде занимает около 15 секунд, и сообщения,
отправленные до готовности, **теряются молча**.

Судья попадёт ровно в этот сценарий.

Поэтому:

1. **Весь одиночный цикл работает без сервера.** Двадцать лучших призраков лежат в
   `static/ghosts.json` и грузятся из файла сцены. Судья приземляется — призраки уже едут,
   с первого кадра, без спиннера и без пустого экрана.
2. Сервер нужен только чтобы принять новое время, обновить таблицу и отдать inbox. Пока он
   просыпается, внизу тихо горит `syncing`, и это ничему не мешает.
3. **Хартбит.** Сервер пишет `Date.now()` в синхронизируемый компонент каждые 2 секунды.
   Клиент считает сервер живым, если значение менялось за последние 6 секунд.
   `isStateSyncronized()` подтверждает только транспорт, а не то, что сервер поднялся —
   на него не полагаемся.
4. Скрипт `npm run bake-ghosts` вытягивает актуальные блобы через
   `npx sdk-commands storage scene get` и перезаписывает `static/ghosts.json`.
   Прогоняется 3 сентября, когда в мире уже будут живые заезды.

### Лимиты сервера, о которые можно убиться

- Память изолята **256 МБ**. Превышение — сервер падает для всех.
- Синхронное исполнение — 10 секунд на такт, async — 60 секунд. Никаких неограниченных
  циклов на сервере, тяжёлую работу размазываем по тикам через аккумулятор `dt`.
- Входящие сообщения — около **300 в секунду на пира**, лишние дропаются.
- Каждое изменение компонента шлёт **весь компонент целиком**, не диф. Поэтому компоненты
  атомарные: то, что меняется часто, отдельно от того, что меняется редко.

## 5. Мобильные правила

- **Портретный режим не поддерживается.** Проектируем только под альбом.
- UI живёт в **Screen Inset Area** — учитываем вырезы, жестовую панель и нативный
  интерфейс Decentraland.
- Тач-таргеты крупнее десктопных. Никакого точного тыканья по 3D-объектам.
- Текстуры UI экспортируем в **2x** разрешении.
- Картинки UI **предзагружаем в скрытом элементе** на старте сцены, иначе при первом
  показе будет белая вспышка.
- **SDK 7.27 или выше**, иначе скейл UI разъезжается между десктопом и мобилой.
- Чат сцена спрятать не может — просто учитываем, что он занимает место.

### Камеры

- Третье лицо во время заезда.
- Cinematic — пятисекундный облёт трассы при входе.
- Orbital — стена рекордов.

### Первые три секунды

Судья приземляется на старте, мимо уже несутся призраки, одна строка текста
(«17 человек прошли эту трассу») и кнопка. **Никакого туториала, никакого пустого экрана.**
Пустой экран на третьей секунде читается как поломка, а не как загрузка.

## 6. Бюджет производительности

Меряем **на реальном Android**, не в эмуляторе, с профилем **High** в Stats Panel.

- Трасса — не больше **25 слитых мешей**. Не 2500 отдельных стен.
- Текстуры — максимум **1024×1024**, дубликаты материалов вычищаем.
- Коллайдеры — **только коробочные примитивы**. С декора коллизии сняты полностью.
  Визуальные меши и коллизионные — раздельные.
- Кольца буста — **эмиссивный материал**, не источники света. Прозрачность дорогая.
- Частиц минимум, лучше анимированные, чем многочисленные.
- В системе воспроизведения призраков: никаких аллокаций внутри цикла, интерполяция между
  сэмплами, частота обновления не выше частоты записи. Пропуск кадров для всего, чему не
  нужен каждый тик.

## 7. Чего мы не делаем — жёсткие запреты

- **Никакого транспорта через `movePlayerTo()` каждый кадр.** Это телепорт, а не движение,
  на телефоне будет дёргаться.
- **Никаких движущихся платформ под игроком.** Единственный «настоящий» способ сделать
  транспорт, и единственный, который развалится за два дня до дедлайна. Мы едем ногами
  под гору, а доска — косметика поверх.
- **Никакого внешнего бэкенда.**
- **Никакого `localStorage` / `sessionStorage`** — их в сцене нет.
- **Никаких шести `AvatarShape`.**
- **Никакой второй механики.** Одна кнопка, одно решение — брать кольцо или нет.
  Каждая идея вида «а ещё давайте добавим» откладывается в `ICEBOX.md` и не обсуждается
  до 2 сентября.
- **Никаких запланированных событий и ведущего.** Это дисквалификация.

## 8. Как работать в этом репозитории

### Проверяй API, не вспоминай его

Decentraland SDK меняется быстро, и в обучающих данных модели он устаревший. Конкретно
известные ловушки:

- Компонент кастомизации тач-контролов в одних источниках называется
  `ScreenControlsComponent`, в других `TouchScreenControls`. **Сверься с доками, прежде чем
  писать.**
- Якоря `AvatarAttach` и API настроек локомоции аватара тоже нужно проверять.

Документация доступна в машиночитаемом виде: к любому URL на `docs.decentraland.org` можно
дописать `.md`, а полный индекс лежит в `https://docs.decentraland.org/llms.txt`. Есть
также параметр `?ask=<вопрос>` для точечных запросов к странице.

Ставь **SDK Skills** до начала работы — без них модель генерирует несуществующие параметры.
Есть **MCP-сервер Creator Hub**, через который можно ходить по сцене, кликать объекты,
снимать скриншоты и смотреть производительность. Используй его для самопроверки.

### Ритм работы

- Мелкими шагами: одна фича — тест — правка — следующая. Не «построй мне всю игру».
- После каждой заметной фичи — превью на **реальном телефоне** через QR из Creator Hub.
- Логи с префиксами `[SERVER]` и `[CLIENT]`, иначе их не различить.
- В `scene.json` держим `logsPermissions` с адресами команды, иначе серверных логов в
  проде не увидеть. `npx sdk-commands sdk-server-logs` — стрим логов.
- `.env` в `.gitignore`. Всегда.

### Тестирование мультиплеера локально

Превью открывается дважды, каждое окно — отдельный игрок, подключаться нужно **разными
адресами**. Оба клиента идут в один локальный сервер. Локальный сервер стартует мгновенно,
поэтому **проблемы холодного старта проявляются только после публикации** — их надо ловить
отдельно, на живом мире.

### Коммиты

Conventional commits, английский, повелительное наклонение:
`feat(ghosts): interpolate playback between samples`.
Один коммит — одно изменение. Ветки от `main`, PR с описанием того, что проверено на
телефоне.
